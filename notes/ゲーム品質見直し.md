# ゲーム品質の見直し

## 方針

機能の数ではなく、短い区間を遊んだときの完成度を上げる。
核は「狙って倒す → 危険を避けてつなぐ → フィーバーで押し切る」。
まず冒頭の戦闘を磨き、その基準を中盤・ボスへ広げる。時間を延ばすための待ち時間は追加しない。
ただし、本編を練習用の内容にはしない。操作習得のチュートリアルと本編の面白さの改善は分ける。

作業前のローカル保存先: `codex/checkpoint-before-opening-review-20260915` / `3c0bb58`。
既存のHUD・マテリアル・建物描画の修正を含む。外部へのプッシュは行っていない。

### チュートリアル側へ移した配置

- 最初は中央の単体。移動と連射を試せるよう、まだ敵は反撃しない。
- 次は左右2機。HPを3にして、通常弾3発とチャージ弾1発の違いを示す。
- 続いて射撃する敵1機。ここから反撃を始め、回避を使う場面を作る。
- 左右から来る移動敵で、追いかけて照準を合わせる段階へ移る。
- 3機編隊を配置し、撃破をつないでためたゲージをフィーバーに使う機会を作る。

- 撃破後の移動と息継ぎを並行させ、二重の待ち時間をなくした。
- フィーバー中は編隊間の進行を加速する。敵が残る戦闘中の進行停止は維持する。

### 不整合の修正

出現済みフラグは開始時に配置データの件数分だけ確保する方式へ変更。
本編26件・チュートリアル11件それぞれの件数に合わせる。距離順やHP等の不正値もコンパイル時に検査する。

### 確認の意味と限界

- 起動放置テスト：描画・進行の安定性を確認する。面白さの評価には使わない。
- 一時的な自動照準・射撃テスト：通常弾、チャージ弾、撃破、チェイン、ゲージ蓄積、フィーバー、次編隊への連係を確認する。
- 自動照準は人間より速く正確なので、到達時間を標準クリア時間とは扱わない。
- テスト用の自動操作は検証後に除去する。通常のゲーム操作は変更しない。
- 実プレイでは、初見で操作が分かるか、狙い直す余裕があるか、次に何をするか迷わないかを確認する必要がある。

## 次に見直す順序

1. 射撃・命中・撃破の音。連射時の音声の寿命・同時発音数を管理してから、通常弾／チャージ／撃破の音を区別する。
2. 冒頭の実プレイ結果で、敵の大きさ・滞在時間・弾速を調整。成功率だけでなく、チャージと回避を使い分ける意味を見る。
3. ステージの構図。新しい素材を大量に増やす前に、建物の高さ、開けた区間、見通し、光の変化で場面を区切る。
4. 中盤とボスへ展開。予告を見て回避し、隙に攻撃する関係を明確にする。

## 回避から攻めへつなぐ残像連撃（2026-09-24）

この節は初期版の記録。回避を発動条件にする仕様は廃止し、現在は末尾「スキルを回避から独立」の仕様を使う。

ユーザーの希望で、SAOの連撃技に着想を得たオリジナルスキル「ファントムレイド」を追加。
作品中の技・音声・素材の再現ではなく、現在のレールシューティングへ組み込む初回実装。
変更前はローカルの `b95887a` / `codex/checkpoint-before-phantom-raid-20260924` に保存した。

### 遊び方・仕様

- ジャスト回避成功で1回分を準備し、Qで発動。準備は時間切れで失われない。
- 通常は最大3機への青い3連撃、フィーバー中は最大5機への金色の5連撃。
- 照準に近い、画面内かつ前方75m以内の敵を選ぶ。対象がいなければ消費しない。
- 雑魚には連撃で印を刻み、最後にまとめて6ダメージ（強化時9）。盾は通常の防御処理を通す。
- ボスは1回ずつ1ダメージ＋最後に5ダメージ（強化時は5回＋9）。反撃チャンス中は通常通り2倍。
- 機体の残像が敵を斬る構成。自機とカメラを敵へワープさせず、通常の移動操作を維持。
- 演出は通常約0.9秒／強化約1.1秒。短い溜め、連撃、決めのスロー、先細りの光刃を表示。
- 攻撃区間は敵弾から保護し、最後に対象周囲の弾だけを払う。保護中にジャスト回避を再取得しない。
- 発動から6秒は再取得不可。無条件連発はできず、以後のジャスト回避で再び準備する。
- タイトル・Hの説明と、右下の準備／連撃数／再取得待ち表示を追加。
- DebugのF1 → ゲーム調整 → デバッグ操作から「残像連撃を準備」「残像連撃 [Q]」でも試せる。

### 実装上の扱い

- 残像は初期化時に5個を確保し、既存のObject3d経路で描画。描画後はブレンドと深度設定を復元。
- 斬撃は画面へ投影した対象位置に描く。エンジンのGPUパーティクル／シェーダーは変更していない。
- 敵ポインタは使用のたびに所属を確認し、削除時にも参照を外す。途中消失は追加報酬なしでスキップ。
- 弾とスキルの撃破処理を共有し、スコア・報酬・ボスクリアの重複や処理漏れを防ぐ。
- クリア成立後は衝突処理を止め、結果表示までの残弾でHPが削られることも防ぐ。
- オリジナル生成音を3種類追加。全12音源・固定25音声枠。実機での聴感調整は今後行う。

### 検証方法

通常プレイと試験配置の結果を混同しないよう、Debug専用に別の検証を設けた。

```powershell

& .\project\tools\RunSmokeTest.ps1 -Configuration Debug -GameplaySeconds 180 -Phantom
# 同じ試験を代表フレームで止めて映像確認。NEXTボタンで進める。
```

通常3機／強化5機の撃破、再取得待ち、途中消失、スキルによるボス撃破、R再挑戦での状態初期化を確認。
ボスのクリア経路検査だけは低HPの試験配置を使用しており、難易度の検証ではない。
実画面では細い曲線だけの初稿を修正し、先細りの光刃と機体残像、青／金の色分けとHUDを確認した。
面白さ・強さのバランスは初回調整。実際に手で遊んだ感触に合わせて調整する。

## ゲーム開始直後の負荷改善（2026-09-24）

変更前を `3c47c74` / `codex/checkpoint-before-startup-perf-20260924` にローカル保存。
ファントムレイドを含む既存変更は保持している。外部へのプッシュはしていない。

### 計測で判明した原因

初期状態では自機弾8・敵弾8・ヒット演出24だけを用意し、本編開始後に毎フレーム
目標数24・24・120まで増設していた。1つのObject3dの生成には複数のGPUバッファ確保が必要で、
開始後の移動・描画と重なっていた。また、戦闘中にも空き予備数を補う増設が続いていた。

修正前Debugの先頭2秒は平均46.45ms、p95 67.29ms、最大80.82ms。
GPUバッファの新規確保714回、予備の生成だけで合計615.76ms。
記録: `generated/smoke-tests/debug-20260924-112139.log`。
修正前Releaseは平均17.97ms、最大51.24ms、新規確保1120回。
記録: `generated/smoke-tests/release-20260924-112219.log`。

### 変更

- タイトルの準備処理中に、既存の目標数まで弾とヒット演出を用意する。
- 戦闘中は使用済みオブジェクトを返して再利用し、予備の毎フレーム増設を削除。
- 画質・モデル・演出数・敵の配置・GPUリソース状態・同期処理は変更しない。
- スモークテストに開始0〜2秒／2〜5秒／5〜10秒の処理時間とGPUバッファ確保数を追加。
  固定配列へ記録して終了時に集計する。測定のための毎フレームのファイル書込はしない。
- 通しテストのログに弾・ヒット演出の予備不足と最大同時弾数を加えた。

先にタイトルで用意する変更だけでも、Debugの先頭2秒は平均18.29ms（約61%減）、
p95 22.16ms、新規確保0回へ改善した。記録: `debug-20260924-112429.log`。
ただし単発の描画待ちスパイクは残る。Releaseの先頭2秒の平均は約18msで同程度であり、
すべての環境・構成で同じFPS改善を保証するものではない。

増設削除後の通し試験: `debug-20260924-112918.log`。
