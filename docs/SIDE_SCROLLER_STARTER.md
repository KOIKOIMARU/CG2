# 2.5D横スクロール基準シーン

## 目的

`samples/side_scroller/SideScrollRuntime`は、3Dモデルを使用しながらゲームプレイを2D平面へ制限するための最小動作例です。完成ゲームの設計ではなく、チーム全員が同じ座標、入力、当たり判定、カメラの前提から実装を始めるために用意しています。

## 座標と単位

- X軸：画面上の左右。右方向を正とする。
- Y軸：高さ。上方向を正とする。
- Z軸：奥行き。カメラから遠ざかる方向を正とする。
- 1ワールド単位：1メートルとして扱う。
- 基準ゲームプレイ平面：`Z = 0`。

プレイヤーは毎フレーム`Z = 0`へ固定しています。背景や前景はZ座標を変えて配置できますが、当たり判定へ参加させるかはゲーム側で明示してください。

## 操作

| 操作 | キー |
|---|---|
| 左右移動 | A / D、または左右矢印 |
| ジャンプ | Space、またはW |
| 初期位置へ戻す | R |
| 透視投影と正投影の切り替え | F5 |

物理キーは`InputActionMap`へ初期化時に登録しています。ゲームロジック内へ`DIK_A`などを直接書き散らさず、操作単位で問い合わせてください。

## 実装されているもの

- 箱モデルによる仮プレイヤーと足場
- 左右移動、重力、ジャンプ、着地
- X軸とY軸を分けたAABB衝突解決
- プレイヤーのZ座標固定
- X方向へ滑らかに追従するカメラ
- 低FOVの透視投影と正投影の比較
- プレイ画面内の操作ガイド

## 現在の制限

- 斜面、回転した床、段差の自動昇降には未対応。
- 高速移動向けの連続衝突判定には未対応。
- 移動床から受け取る速度には未対応。
- コントローラー入力には未対応。
- アニメーション状態機械は未実装。

これらは作品仕様が決まってから必要なものだけ追加します。汎用化を急いで未使用機能をengine層へ増やさないでください。

## ファイルの責務

- `engine/collision/Collision`：ゲームを限定しないAABB計算。
- `engine/io/InputActionMap`：操作IDとキーボード入力の対応付け。
- `engine/3d/Camera`：透視投影と正投影の生成。
- `samples/side_scroller/SideScrollRuntime`：移動、ジャンプ、着地、カメラ追従。
- `app/AppSceneFactory`：エディタのプレイモードへランタイムを接続。

## チーム作品へ移す順番

1. チーム作品用ランタイムを`app`または専用ゲームフォルダへ作る。
2. `IEditorPlayRuntime`を実装する。
3. 座標規約と`InputActionMap`の使い方を維持する。
4. 必要な移動・衝突処理だけ`SideScrollRuntime`から移す。
5. `AppSceneFactory`の生成先を正式ランタイムへ差し替える。
6. Debug Layerを有効にして実画面を確認する。
